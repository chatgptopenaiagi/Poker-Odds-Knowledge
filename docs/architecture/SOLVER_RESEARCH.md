## Selected solver's actual algorithm

The adapter uses the real upstream `CfrPlusRiverSolver` traversal with **`DiscountedCfrTrainable`**, whose inspected constants are alpha 1.5, beta 0.5, gamma 2 and theta 0.9. Its accumulated discounted average is exported and checked, with tiny row normalization for float rounding. The separate upstream `CfrPlusTrainable` was excluded: its average-strategy accessor returns the current strategy in this pin. POK does not silently rename either algorithm into a different CFR guarantee.

The small adapter supplies the bounded explicit river tree, lifecycle, strict JSON boundary and a separately verified best-five hand comparator. Compatibility patches migrate the selected fastjson imports and supply a direct-tree constructor; they do not replace CFR updates. No giant evaluation dictionary, turn/flop solve, GUI framework, model or GPU dependency is needed. The current scope excludes chance nodes, future streets, rake, side pots, short all-in raises and more than two active players.

The actual JVM run uses one compute thread and fixed iteration budgets. Direct verification jobs used a 256 MiB maximum heap, 15-second solver deadline and 17-second parent timeout. The service path separately applies a Windows process-memory job cap of 512 MiB; JVM heap and process committed memory are different limits. The independent quality job verifies mathematics through the direct owned CLI, while service guard/security tests establish service resource handling separately.

Modern selected JSON dependencies are fastjson2 **2.0.65**, Jackson core/databind **2.22.3** and annotations **2.22**, all Apache-2.0 according to retained adapter metadata/notices. Their hashes are pinned in `engine-adapters/java/dependencies.json`. Solver MIT and dependency notices must accompany its distribution. POK's product license is not changed by this selection.

## Independent verification actually executed

`scripts/solver-oracle.py` rebuilds the betting tree and sequence constraints from inputs. It uses PokerKit **0.7.6** for terminal hand rankings and SciPy **1.18.1** / NumPy **2.5.3** for primal/dual LPs and exact best responses. These pinned packages were installed only in a new ignored project-local environment using Python **3.14.7**; the earlier verification environment and Anaconda base were unchanged. Neither Python nor SciPy ships as a browser/Android runtime dependency.

Seven Python unit tests passed, including a separate **16×4 normal-form payoff matrix** whose equilibrium agrees with sequence form, exact blocker-conditioned value **−25/7 chips**, suit/weight-scale invariance, uncalled-raise return, impossible assignments and malformed policies. The real Java comparator separately matched PokerKit on **10,011** generated/structured 5/6/7-card hands with **zero category, ordering or tie disagreements**. See [JAVA_POKERKIT_VERIFICATION](../strategy/JAVA_POKERKIT_VERIFICATION.json).

Six original weighted scenarios used the fixed plan **500 / 2,000 / 10,000 iterations**, producing 18 actual Java outputs. All passed the predeclared **NashConv ≤0.5 chips** and **Java metric/action-EV agreement ≤0.001 chips** gates. Independent primal/dual tolerance is 1e-8 chips. Every node/action, terminal payoff, compatible rank pair, average-policy row, positive-reach conditional EV and own/opponent reach was checked. [SOLVER_QUALITY.json](../strategy/SOLVER_QUALITY.json) retains every run, full traces, input/output hashes and tolerances. Zero-opponent-reach fallback EV is explicitly excluded from conditional-value claims.

The final JAR was rebuilt to reject trailing JSON; the same 18-job plan was rerun once to align provenance with that parser fix. Earlier evidence was preserved. The final verified JAR hash is `507a3ec2ca578f96550ae840f95ed9a332f2e64bbe8b3d8e7fbf719ab82e115e`. This was not a changed-budget search for favorable results. Gaps are nonmonotonic across some checkpoints; more iterations are not advertised as automatic improvement.

Final 10,000-iteration independent NashConv values range **0.005955–0.186888 chips** for these 100-chip pots. This certifies only the declared finite river abstractions to the stated numerical checks, not unrestricted NLHE/GTO, a per-hand error bound, live advice or professional playing strength. Turn solving and six-active-player strategy remain **NOT_RUN / unsupported**. Browser workflow, API authorization, APK build and Android execution have separate acceptance gates.
