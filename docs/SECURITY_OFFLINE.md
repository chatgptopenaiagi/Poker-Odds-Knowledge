# Local security, offline operation and backups

HIL uses play chips only. The built application has no payment, prize, real-money table, external poker client, HUD, scraping, narration model, or cloud API integration. Cards, legal actions, payouts and probability answers come from dedicated deterministic code, not a language model. There is no arbitrary shell or math execution endpoint. CLA and Maxima are development/evidence tools and are not browser backends.

The production bundle consists of static HTML, JavaScript, CSS and local assets served by the existing Apache. Node and the isolated Python verification environment are development tools. No Python, PHP, model, database server, Node development server or internet service is needed for normal play. The application uses one on-demand Web Worker per active analysis client; terminating the worker cancels its calculation, and generation IDs reject old responses. Probability work never consumes the deal RNG. Deployment and offline-browser test results are reported separately in the delivery report; these design facts do not substitute for those tests.

Only public build output belongs in the dedicated served directory. The source tree, Git, dependency caches, Python environment, verification transcripts and CLA evidence remain outside the Apache DocumentRoot. The app-scoped Apache access rule must reject nonlocal requests. A localhost hyperlink by itself does not prove LAN isolation; see the deployment verification evidence for the actual rule and result. HIL does not change Apache listeners, firewall settings, global services, PATH, or other sites.

HIL saves state under IndexedDB database `hil-study-v1`, object store `state`, key `hil:session`. Each save atomically includes current action state and completed history in one read/write transaction. An optimistic revision comparison rejects competing writes from another tab. Hand action revisions independently reject repeated/stale clicks. The browser profile and origin own this storage: `localhost` and `127.0.0.1`, different ports, private windows and different browsers can all have separate histories. Clearing browser data can erase progress. Browser storage is private to the profile but is not encrypted by HIL.

JSON export is a human-portable backup. It includes enough private local information to replay saved hands, including their full deal. Keep backups in a trusted personal location. Sharing them reveals the cards in those hands; the browser application does not claim adversarial secrecy. Export before a confirmed reset. Exports are downloads to the user's browser-selected directory; HIL does not upload histories.

Imports are limited to 5 MB of UTF-8 text. Schema 1 is the initial format; unknown versions are rejected without changing existing data. There is no invented migration from a nonexistent older format. Limits also bound hand count (200), actions per hand (500), drill attempts (5,000), saved scenarios (100), text lengths and nested object depth. HTML/script-like text and prototype-mutating keys are rejected. Imported names/text are never executed. Initial decks, seat counts, stacks, blinds, buttons, IDs, versions and logs are validated; final stacks and payouts are rebuilt from the initial state and legal actions instead of trusting claimed totals. Duplicate completed-hand and drill-attempt IDs are rejected. Imported drill answers are regraded using the matching local lesson/version; correctness flags supplied in the backup are not trusted.

Scenario imports validate card notation, unique known cards, board size, range syntax, weights, blockers and at least one compatible joint opponent assignment. Feasibility validation has a bounded work budget and fails clearly rather than hanging. User-authored scenarios and histories remain user-authored records, not authenticated evidence of how someone played. This application is a personal learning tool, not a regulated gaming or auditing system.

Practice observations contain the actor's cards and public state only. Opponent holes, burns, future deck order and hero-only analysis are excluded from the bot input. Teaching reveal changes what the learner can see, not what bots receive. Range-based equity and equity conditional on revealed hands are separate calculations. Future cards and folded hidden cards are not removed from the analysis deck unless explicitly supplied as known dead cards in a study scenario. Completed-hand review can expose the deal; a branch leaves the saved original intact.
