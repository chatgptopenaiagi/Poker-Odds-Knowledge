## Preserved implementation

- i18next 26.4.2 uses stable flat keys, explicit English fallback and CLDR plural rules. Intl.NumberFormat and Intl.DateTimeFormat helpers are available. Native names have no country flags. Arabic, Hebrew, Persian and Urdu declare RTL. The global notice identifies machine drafts and English fallback in the selected language.
- Cards, ranks, range notation, lesson IDs, formula symbols, JSON field names and engine method identifiers stay technical identifiers. Formulas retain ASCII numeric literals so fixture comparisons do not change with locale. User-facing numeric formatting uses Intl where connected; some legacy numeric displays remain unchanged.
- No remote font, translation request or language service is required. System glyph availability depends on the Windows/browser installation. Glyph inspection and native linguistic review are separate from mechanical tests.
- Simplified Chinese is the requested Chinese language target. A Traditional Chinese Appearance variant exists but is not a complete selectable locale and is not counted as a forty-second language.

## Accurate remaining scope

Full authored-product translation is **PARTIAL**. The 130 extracted legacy detail strings and nine glossary definitions are currently fully translated only in English/Romanian. Additional original core help paragraphs remain English fallback outside these locales. Platform controls are complete for the languages with full counts above; the remaining platform catalogs were deferred at the user's later engine-selection checkpoint. Raw engine errors, some accessibility labels, diagnostic details, and later-added interface strings still need an extraction audit. No missing catalog text is counted as a translation; i18next returns readable English rather than exposing raw keys, and the localized notice discloses this.

Email templates are local text assets. A complete translated email does not prove external mail delivery. Source metadata: implementation-agent machine draft, version 1, no independent reviewer, no paid model translation loop.

## Verification

The dedicated i18n suite mechanically checks all 41 catalogs: core/lesson presence, unchanged fixed formula lines for all 39 new lesson languages, unchanged answer grading, email URL placeholders, CLDR category availability, fallback disclosure, native names, RTL metadata, safe strings and Intl formatting. It does not claim semantic or native review. At the checkpoint, `npx vitest run tests/i18n.test.ts tests/lessons.test.ts` passed 50 tests; TypeScript compilation passed before this report was generated. Browser screen coverage is recorded separately by the root agent; generating catalogs alone does not establish a rendered 41-language screen sweep.

## Rebuilding catalogs

The scripts/translation-*.mjs groups hold reviewed-by-code-only translation drafts and write deterministic JSON. translation-build.mjs centralizes invariant formula strings; translation-mail.mjs creates mail/notice maps. translation-extract.ts was a one-time extraction of the HIL source and should not be rerun to overwrite newer catalogs. Run translation-report.ts with the pinned project tsx loader to refresh the exact matrix.
