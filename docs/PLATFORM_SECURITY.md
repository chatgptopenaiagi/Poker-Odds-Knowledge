# Platform security, moderation and retention

Public accounts, community and cloud coaching are an adult educational beta (18+). Email signup requires affirmative acceptance; external signup is implicit-disabled and requires an explicit signup request with acceptance. No birthday, legal identity, contacts, precise location or inferred nationality is collected. Offline guest study remains independent of account registration.

Better Auth supplies scrypt password hashing, verification/recovery tokens, state/PKCE, session cookies, expiry and revocation. Cookies are HttpOnly, SameSite=Lax, production Secure, with no browser-readable session-token store. Cookie session caching is disabled so revocation and sanctions apply to existing clients. Login failures are normalized; duplicate registration and recovery use generic results. Dedicated secrets are never shipped to the client. Auth rate limits use SQLite, and custom writes have per-member limits. TLS and reverse-proxy headers are production operator responsibilities; forwarded headers must be stripped and regenerated by that proxy.

Recovery links expire after 15 minutes, verification links after 30 minutes, sessions after seven days with hourly refresh. Password recovery revokes all sessions. Account deletion requires a fresh session and a single-purpose email link opened with the same account session. The last owner is protected. Deletion removes profile/sync/notification data and anonymizes/hides authored content; private coach chats are removed and usage rows lose their user identifier. Audit rows retain pseudonymous actor/target identifiers and reason text for accountability. They are application append-only via SQLite triggers, not cryptographically immutable.

The local test-mail sink is explicitly requested by the staging launcher, memory-only, bounded to 200 messages and inaccessible in production mode. Its local inbox is deliberately visible to the workstation user, so use isolated study identities and passwords. It is not real mail delivery and never runs on a public listener. SMTP uses server-side Nodemailer with TLS/STARTTLS, short timeouts, no debug logs and plain text localized templates. No production tokens/links are logged. The operator must select a real sender, configure a delivery service and test receipt before public signup.

Moderation dictionary v1 has 46 draft entries across all 41 target locales. Entries record locale, literal phrase, safe word/phrase match mode, category, severity, exceptions, source, enabled state and draft/review status. Coverage is a starting signal, not comprehensive abuse detection or linguistic approval. Every locale's human review state is NONE. English has additional threat/spam/profanity seeds; several other languages include threat examples; most locales initially contain a single insult signal.

All locale codes with at least one draft entry: en, ro, de, fr, es, pt, it, nl, sv, da, nb, fi, pl, cs, sk, hu, sl, hr, sr, bg, el, tr, uk, ru, ar, he, fa, hi, bn, ur, ta, te, mr, th, vi, id, ms, ja, ko, zh-Hans, sw. Actual counts are exposed by the CP's Languages section and can be recomputed from `seedDictionary`.

Matching normalizes NFKC, casing, selected zero-width evasions and whitespace. Unicode letters/numbers bound Latin-like word matches; CJK matching is literal. There are no user-supplied regexes. Quoted/classroom/code context is attached as a caution signal rather than hidden automatically. Multiple dictionary signals form one human-review report. Automated matches never warn, mute, suspend or ban anyone. Tested false-positive cases include innocent substrings, quoted classroom insults, Japanese ordinary text, Arabic threat text, and full-width evasion. This is mechanical evidence; native-language false-positive review remains NOT_RUN.

Authorized staff can warn, temporarily mute, temporarily suspend, ban, hide/restore content and reverse a restriction, with recorded reason, evidence reference, actor and expiry. Temporary actions are capped at thirty days and enforced server-side immediately on both old and new sessions. A mute restricts community posting while preserving study history. A suspension/ban restricts ordinary platform APIs; account notices and appeals remain available. Dictionary activation requires a real preview with sample messages, a random user-bound digest token that expires after ten minutes, and a reason. Preview tokens are consumed; altered entries or replay are refused. Versions can be rolled back with audit.

Default retention: local guest data stays in the existing browser notebook until explicit deletion. Server study sync and profiles remain until account deletion or explicit sync clearing. Community and case records remain until author/staff action or account deletion. Audit is retained until an operator's documented backup/database lifecycle; no automatic audit purge is claimed. The experimental operator must define jurisdiction-appropriate maximum retention and backup expiry before public signup. Coach retention is separately bounded by its server setting. Account exports are private and exclude password hashes, sessions, OAuth tokens and secrets. No request logging middleware records posted content.

No attachments, external-table advice, payments, purchasable chips, cash wagering or third-party poker automation are implemented. Content reports, appeals and moderation work locally; SMTP notifications and real identity-provider approval remain external setup items. Cross-user database/API tests establish the checked cases, not comprehensive penetration-test certification.
