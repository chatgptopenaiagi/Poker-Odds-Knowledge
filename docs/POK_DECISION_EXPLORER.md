# Decision Explorer v1

Hand Review now offers a temporary **River decision example**, plus a **Decision Explorer · Fold vs Call** panel for the selected replay position. Opening or inspecting an alternative does not execute it. There are no action, save, fork or progress callbacks in the viewer. The existing replay model and shared Card renderer are retained.

The supported context is deliberately narrow: the hero acts on the river in a two-seat hand, both players remain eligible, the call is positive and fully covers the outstanding wager, contributions become equal after calling, and there are no recorded uncalled returns. Earlier streets, completed hands, another actor's turn, checks, short calls, unequal pot eligibility and invalid visible cards/chips are refused. Other legal actions may exist, but their EV is not modeled.

`terminalDecisionContext` projects the existing rules engine's legal actions and observation into an immutable snapshot: hand identity/revision, hero cards, public board, pot and call cost. It excludes opponent holes, burns, deck and future actions. `decisionRequest` accepts an explicit opponent-range assumption, applies known-card blockers and uses the existing validated analysis contract and EngineClient. The default random range means all unblocked two-card combinations; revealed opponent cards are never silently substituted.

The same completed worker result supplies expected pot share, the existing Decision Intelligence explanation and the comparison. At the decision point, Fold EV is zero: committed chips are sunk. Call EV is equity*(P+C)-C, where P includes the opponent's wager and C is the new call. There is one fully eligible terminal pot, no rake, refunds or future betting. Exact enumeration is exact only for those range/model assumptions. Monte Carlo retains the engine's fixed-N interval and seed; an overlapping interval is statistically uncertain, not an action recommendation. No bet/raise EV, full strategic EV or universal GTO is claimed.

Range, engine, method and sample edits cancel and invalidate the old result. The existing client validates request ID, revision, engine and input hash and terminates its owned worker. A separate snapshot key prevents a replaced replay context from displaying an old result even before effect cleanup. Replay navigation unmounts the old viewer. Cancelled, partial and failed work produce no substitute comparison.

The example is generated by the actual reducer with an explicit teaching deck. A royal board makes every valid opponent combination tie; the engine computes the result. The displayed price/EV is not hardcoded. With pot 40, call 20 and share 1/2, Fold EV=0, Call EV=10 and the threshold is 1/3. An independent weighted case uses hero AA on 2c 3d 7h 8s 9c: AA ties AA, beats KK and loses to three nines. Weights 0.5/0.25/0.75 give share (0.5*0.5+0.25)/1.5=1/3 and break-even Call EV. Pure KK and three-nines ranges give +40 and -20 respectively. These are deterministic reference cases, not a new external oracle.

Explorer selections/ranges/results are intentionally temporary. Leaving the view, moving replay position or refreshing resets them. Existing saved hands, progress and appearance preferences retain their original persistence behavior. No schema migration or storage key is added. English/Romanian follow the existing helper and locale formatting; other locales explicitly fall back to English. Translations are not claimed professionally reviewed. Keyboard controls, shared faces/colors, high contrast, reduced motion, narrow width and enlarged text/cards are checked in the built browser.

Tests distinguish real worker/browser execution from the existing simulated worker protocol tests for deliberately injected stale replies. Synthetic notebook fixtures verify original hands and progress remain unchanged. Offline tests block external network before first load while leaving the loopback HTTP origin reachable. This is neither file:// nor installed-app acceptance. No account, SQL Server, WSL, CAE or AI dependency is introduced.
